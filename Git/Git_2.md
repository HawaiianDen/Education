# 6. Ветвление и слияние

## Создание веток

Ветки позволяют параллельно вести разработку, изолируя новые функции или эксперименты от основной линии (обычно `main`).

```bash
# Создать новую ветку (без переключения)
git branch feature

# Создать и сразу переключиться на новую ветку
git checkout -b feature
# или (современный синтаксис)
git switch -c feature
```

---

## Переключение между ветками

```bash
# Переключение на существующую ветку
git checkout feature
# или
git switch feature

# Вернуться на предыдущую ветку
git checkout -
```

Совет: используйте `git switch` вместо `git checkout` для более явного управления ветками.

---

## Слияние веток

Чтобы объединить изменения из другой ветки в текущую:

```bash
# Находимся в ветке main
git merge feature
```

Виды слияния:
- **Fast-forward** — простое перемещение указателя, если ветка шла строго вперёд.
- **Merge commit** — создаётся отдельный коммит слияния, если есть параллельные изменения.

---

## Удаление веток

После завершения работы ветку можно удалить:

```bash
# Удалить локальную ветку
git branch -d feature

# Принудительное удаление (если ветка не слита)
git branch -D feature

# Удалить ветку на удалённом репозитории
git push origin --delete feature
```

# 7. Разрешение конфликтов

## Причины возникновения конфликтов

Конфликты возникают, если в разных ветках изменены одни и те же строки файла или затронуты одинаковые области структуры проекта.

Чаще всего — при выполнении:
- `git merge`
- `git rebase`
- `git pull` (так как включает merge или rebase)

---

## Маркеры конфликтов в файлах

При конфликте Git оставляет специальные маркеры в файле:

```text
<<<<<<< HEAD
Версия из текущей ветки
=======
Версия из объединяемой ветки
>>>>>>> feature
```

Разработчику нужно вручную выбрать, какая версия остаётся, либо объединить их.

---

## Стратегии разрешения конфликтов

- **Принять изменения текущей ветки:**
  ```bash
  git checkout --ours path/to/file
  ```
- **Принять изменения другой ветки:**
  ```bash
  git checkout --theirs path/to/file
  ```
- **Вручную объединить** и затем отметить файл как решённый:
  ```bash
  git add path/to/file
  ```

После разрешения всех конфликтов:
```bash
git commit
```

---

## Инструменты для визуализации конфликтов

- Встроенные средства IDE (IntelliJ IDEA, VS Code, PyCharm).
- `git mergetool` — вызов внешнего инструмента для объединения.
- Специализированные утилиты: Meld, KDiff3, Beyond Compare.

# 8. Работа с удалёнными репозиториями

## Добавление remote

```bash
git remote add origin https://github.com/user/repo.git
```

`origin` — стандартное имя для основного удалённого репозитория.

---

## Просмотр remotes

```bash
git remote -v
```

Показывает список удалённых репозиториев и их URL.

---

## Получение изменений

- `git fetch` — скачивает изменения из удалённого репозитория, но не сливает их с локальной веткой.
- `git pull` — выполняет `fetch` + автоматическое слияние (или rebase, если настроено).

Примеры:
```bash
# Получить изменения без слияния
git fetch origin

# Получить и объединить с текущей веткой
git pull origin main
```

---

## Отправка изменений

```bash
# Отправить локальную ветку в удалённый репозиторий
git push origin feature

# Установить отслеживание для ветки
git push -u origin feature
```

# 9. .gitignore файл

## Назначение и синтаксис

Файл `.gitignore` указывает Git, какие файлы и папки нужно игнорировать (не отслеживать и не добавлять в коммиты).

## Паттерны игнорирования

- `*.log` — все файлы с расширением `.log`.
- `build/` — папка `build` и её содержимое.
- `!important.log` — исключение (не игнорировать `important.log`).

## Глобальный .gitignore

Можно задать правила, которые будут применяться ко всем репозиториям пользователя:

```bash
git config --global core.excludesfile ~/.gitignore_global
```

Пример глобального `.gitignore_global`:
```text
*.swp
*.bak
.DS_Store
Thumbs.db
```

## Типичные шаблоны для разных языков

- **Python:** `__pycache__/`, `*.pyc`, `.venv/`
- **Node.js:** `node_modules/`, `npm-debug.log`
- **Java:** `target/`, `*.class`
- **C++:** `*.o`, `*.exe`, `build/`
- **IDE:** `.idea/`, `.vscode/`, `*.iml`

Готовые шаблоны для разных языков и сред доступны в репозитории [github/gitignore](https://github.com/github/gitignore).
