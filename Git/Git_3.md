# 10. Отмена изменений

## Отмена в рабочей директории

Если файл был изменён, но вы хотите вернуть его к последнему сохранённому состоянию:

```bash
git checkout -- file.txt
```

> ⚠️ В новых версиях Git рекомендуется использовать `git restore`:
```bash
git restore file.txt
```

---

## Отмена в staging area

Если файл был добавлен в **staging area** (`git add`), но вы хотите убрать его оттуда:

```bash
git reset HEAD file.txt
```

или (современный синтаксис):
```bash
git restore --staged file.txt
```

---

## Отмена коммитов

- **Создать обратный коммит (revert):**
```bash
git revert <commit_hash>
```
Создаёт новый коммит, отменяющий изменения указанного.

- **Сброс истории (reset):**
```bash
git reset --soft <commit_hash>   # сохраняет изменения в staging
git reset --mixed <commit_hash>  # сохраняет изменения в рабочей директории
git reset --hard <commit_hash>   # удаляет изменения полностью
```

---

## Восстановление удалённых файлов

Если файл был удалён и вы хотите его вернуть:

```bash
git checkout HEAD file.txt
# или
git restore file.txt
```

# 11. Перебазирование (Rebase)

## Отличия rebase от merge

- **Merge** сохраняет историю ветвлений, добавляя merge-коммит.
- **Rebase** «переписывает» историю, перенося коммиты одной ветки поверх другой.

Пример:
```bash
# Переносим изменения из feature поверх main
git checkout feature
git rebase main
```

---

## Интерактивное перебазирование

```bash
git rebase -i HEAD~3
```

Позволяет:
- изменить порядок коммитов,
- объединять (squash) коммиты,
- редактировать сообщения,
- удалять коммиты.

---

## Изменение истории коммитов

С помощью `rebase -i` можно:
- уменьшить количество мелких коммитов,
- переписать историю для большей читабельности.

⚠️ Не рекомендуется менять опубликованную историю (в `main` или других общих ветках).

---

## Best practices использования rebase

- Использовать для локальной очистки истории.
- Не применять к веткам, которые уже были отправлены на общий сервер.
- Предпочитать `merge` для командной работы, если есть сомнения.

# 12. Работа с тегами

## Создание тегов

```bash
git tag v1.0
```

## Аннотированные теги

Содержат автора, дату и сообщение:
```bash
git tag -a v1.0 -m "Release version 1.0"
```

## Пуш тегов

```bash
git push origin v1.0     # отправить один тег
git push --tags           # отправить все теги
```

## Управление версиями через теги

Теги часто используют для пометки релизов (например, `v1.0`, `v2.1.3`). Совместно с GitHub/GitLab теги формируют релизы.

# 13. Stash и временное сохранение

## Сохранение изменений

```bash
git stash
# или с сообщением
git stash save "Work in progress"
```

---

## Просмотр stash

```bash
git stash list
```

Пример вывода:
```
stash@{0}: WIP on main: 1234567 Добавил функцию
```

---

## Восстановление изменений

```bash
git stash apply       # применяет последний stash, но не удаляет

git stash pop         # применяет и удаляет из списка
```

---

## Удаление stash

```bash
git stash drop stash@{0}   # удалить конкретный stash

git stash clear            # удалить все stash
```
