# Git — Уровень 5: Рабочие процессы (Workflows)

## 18. Популярные Git Workflows

### GitFlow
Классический процесс, популярный в крупных проектах.
- Ветки: `main` (production), `develop` (основная разработка), `feature/*`, `release/*`, `hotfix/*`.
- Плюсы: чёткое разделение задач.
- Минусы: сложность для небольших команд.

### GitHub Flow
Простой и популярный в open-source.
- Работа в ветке от `main`, далее Pull Request.
- После ревью и тестов — merge в `main`.
- Подходит для быстрых итераций.

### GitLab Flow
Ближе к GitHub Flow, но с поддержкой *environment branches* (`production`, `staging`).
- Удобен при использовании GitLab CI/CD.

### Trunk-Based Development
- Все разработчики коммитят часто в `main` (trunk).
- Фичи скрываются *feature flags*.
- Плюсы: быстрые релизы, простая история.
- Минусы: требует дисциплины и CI/CD.

## 19. Code Review и Pull Requests

### Создание качественного PR
- Один PR = одна задача.
- Изменения маленькие и понятные.
- Хорошее описание (что сделано, зачем, как тестировать).

### Best practices для ревью
- Проверять читаемость кода, архитектуру и тесты.
- Обсуждать идеи, а не людей.
- Использовать чеклисты.

### Работа с комментариями
- Исправлять по замечаниям.
- Помечать resolved.
- Обсуждать спорные вопросы в PR, а не в чате.

### Интеграция с CI/CD
- Автотесты и линтеры должны запускаться при каждом PR.
- PR не мёржится при падающем пайплайне.

## 20. Интеграция с инструментами

### GitHub / GitLab / Bitbucket
- **GitHub:** PR, Actions (CI/CD), Codespaces.
- **GitLab:** Merge Requests, встроенный CI/CD.
- **Bitbucket:** Pipelines, тесная интеграция с Jira.

### Интеграция с IDE
- **VS Code:** расширения GitLens, GitHub Pull Requests.
- **IntelliJ IDEA:** встроенный Git, поддержка PR.

### Git в CI/CD
- Автоматический `checkout` кода.
- Запуск тестов, линтеров, сборок.
- Автодеплой после merge.

### Автоматизация через Git APIs
- GitHub REST/GraphQL API.
- GitLab API.
- Автоматизация задач: создание веток, PR/MR, метки, релизы.
